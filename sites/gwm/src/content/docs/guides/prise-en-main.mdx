Ce guide enchaîne le parcours de premier usage : créer un worktree, le lister,
s'y déplacer, ouvrir la TUI, puis nettoyer. Il suppose gwm
[installé](/guides/installation/).

## Créer un worktree

La forme est `gwm create <type> <issue> <desc>` :

```sh
cd /chemin/vers/votre/repo
gwm create feat 42 user-authentication
```

Cette commande crée en une fois :

<Steps>

1. Un **worktree** dans `~/cc-worktree/<repo>/feat-42-user-authentication`.
2. Une **branche** nommée `feat/#42-user-authentication`.
3. Une entrée git `branch.feat/#42-user-authentication.gwm-base` qui ancre le
   tronc d'origine (utilisée plus tard pour résoudre la base de review).

</Steps>

Le slot `<desc>` est **normalisé en kebab-case** : `"User Authentication"`,
`user authentication` et `User_Authentication` deviennent tous
`user-authentication`. Les types pris en charge par défaut sont `feat`, `fix`,
`hotfix`, `docs`, `test`, `refactor`, `chore`, `perf`, `ci`, `build` — voir la
[référence `.gwm.toml`](/reference/gwm-toml/).

<Aside type="tip" title="Bootstrap par dépôt">
  Si le dépôt a un `.gwm.toml` décrivant une surface de bootstrap, le **premier** `gwm create` ouvre
  une invite de confiance unique avant d'exécuter quoi que ce soit. Voir [Trust ledger
  (TOFU)](/concepts/trust-ledger/) et [Bootstrap par repo](/concepts/bootstrap/). Sautez-le avec
  `--no-bootstrap`.
</Aside>

## Lister les worktrees

```sh
gwm list                  # table lisible
gwm list --format=names   # un nom par ligne (pour la complétion shell)
gwm list --detect-pr      # ajoute une colonne PR (un appel gh par worktree)
```

`--detect-pr` est **désactivé par défaut** pour que le listing simple reste sans
réseau.

## Se déplacer dans un worktree

Un binaire seul ne peut pas changer le répertoire du shell parent — utilisez la
résolution fuzzy via substitution de commande, ou le wrapper `gcd` :

```sh
cd "$(gwm cd auth)"   # résolution fuzzy : « auth » → feat-42-user-authentication
gcd auth              # idem, via le wrapper installé par `gwm shell-init`
gcd                   # sans argument : ouvre un sélecteur interactif
```

`gwm cd` sort `0` sur une correspondance unique, `1` sur un échec ou une
ambiguïté — le wrapper ne fait alors pas de `cd`. Le même moteur fuzzy alimente
le filtre de la TUI.

## Ouvrir la TUI

Lancé sans sous-commande, `gwm` ouvre la TUI sur le dépôt courant :

```sh
gwm
```

Vous y naviguez et agissez au clavier (création, suppression, launchers, filtre).
Tour complet : [La TUI](/guides/tui/).

## Supprimer un worktree

```sh
gwm remove auth                 # supprime le worktree, garde la branche
gwm remove auth --delete-branch # supprime aussi la branche locale (destructif)
gwm remove auth --dry-run       # affiche le plan, ne détruit rien
```

La branche **survit par défaut** — seul `--delete-branch` la supprime. En cas
d'erreur, `gwm undo` ressuscite la dernière suppression.

## Vérifier la santé du dépôt

```sh
gwm doctor
```

`gwm doctor` exécute une batterie de vérifications et sort `0` / `1` / `2` selon
la gravité — pratique en CI ou dans un hook pre-commit. Détail par vérification :
[Diagnostic (doctor)](/guides/doctor/).
