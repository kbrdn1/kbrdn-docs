<Section pad="column" label="Ce que c'est" id="about">

**gwm** crée un worktree isolé par branche en une seule commande, en suivant la
convention `<type>/#<issue>-<desc>`, et prépare chacun via un bootstrap décrit
dans `.gwm.toml`. Une branche est un dossier physique : son propre `target/`,
ses propres dépendances, sa config locale. Rien à stasher, rien à recompiler à
chaque bascule.

C'est un binaire unique et autonome. Les opérations de worktree passent par
libgit2 vendored : pas de sortie shell à parser, pas de `gwq` à installer
d'abord.

</Section>

<Section pad="column" label="Installation">

```bash
# Homebrew
brew install kbrdn1/tap/gwm

# Archives précompilées, sans toolchain Rust
cargo binstall gwm-cli

# Depuis crates.io
cargo install gwm-cli
```

`gwm` seul ouvre la liste. Tout le reste est à une touche : `/` filtre, `2`
donne le focus à la sidebar, `n` crée, `L` bascule dans lazygit, `O` ouvre le
worktree dans votre éditeur.

<Capture
  src={palette}

Chaque pane est documenté dans [le guide de la TUI](/fr/tui/), des raccourcis
clavier à la palette de commandes et aux thèmes.

<Section pad="column" label="Ce que ça apporte">

<FeatureRow n="01" title="Une commande par worktree">
  `gwm create feat 12 ma-feature` ouvre la branche `feat/#12-ma-feature`, son worktree, et exécute
  le bootstrap du dépôt. `gwm remove` démonte le tout, avec `--dry-run` pour regarder avant.

  <Capture
    src={createBootstrap}
    alt="Sortie terminal : gwm init écrit un .gwm.toml depuis le preset rust, puis gwm create ouvre la branche feat/#1-health-check, son worktree, et affiche le rapport de bootstrap"
    cmd="gwm create feat 1 health-check --allow-bootstrap"
    tag="CLI"
    caption="D'un dépôt vide à un worktree bootstrappé - et le bootstrap dit exactement ce qu'il a fait, hook par hook."
  />
</FeatureRow>

<FeatureRow n="02" title="Un bootstrap qui appartient au dépôt">
  `.gwm.toml` décrit conventions de branche, copies de fichiers, gardes regex, invariants no-symlink
  et hooks de cycle de vie. Tous ceux qui clonent obtiennent les mêmes worktrees, et un trust ledger
  TOFU demande avant d'exécuter quoi que ce soit.

  <Capture
    src={trustLedger}
    alt="gwm affichant toute la surface de bootstrap d'un .gwm.toml non approuvé - chemin, origine, hash, copies et commandes - avant de demander l'approbation"
    cmd="gwm create feat 4 stripe-gateway"
    tag="Trust"
    caption="Un .gwm.toml non approuvé montre toute sa surface - chaque copie, chaque commande - avant qu'une seule ne s'exécute."
  />
</FeatureRow>

<FeatureRow n="03" title="L'issue et la PR, dans le worktree">
  Une branche nommée `feat/#42-…` se lie à l'issue #42 sans configuration, `gh` ou `glab` récupère
  son état en direct, et la PR détectée s'affiche à côté - titre, état, CI. Le lien vit dans la
  config git, par branche : il survit à un déplacement et n'est jamais commité.

  <Capture
    src={githubLinking}
    alt="La sidebar gwm affichant une issue auto-liée et une pull request ouverte détectée par gh, avec son statut de CI"
    cmd="gwm status"
    tag="GitHub"
    caption="Issue auto-liée depuis le nom de branche, PR détectée, CI à 8/9 - sans quitter la liste."
  />
</FeatureRow>

<FeatureRow n="04" title="Une TUI quand le CLI ne suffit plus">
  `gwm` seul ouvre une interface ratatui : filtre, sidebar de statut, overlays lazygit et shell
  intégrés, palette de commandes, et un keymap remappable en direct depuis le panneau de réglages.

  <Capture
    src={sideBySide}
    alt="La TUI gwm en disposition côte à côte, sidebar de statut à gauche et liste des worktrees à droite"
    cmd="gwm  ›  Space"
    tag="Layout"
    caption="Space fait tourner la disposition auto → côte à côte → empilé, v bascule la sidebar de gauche à droite."
  />
</FeatureRow>

<FeatureRow n="05" title="Pensé aussi pour les scripts">
  `--format=json` sur `list`, `doctor` et `path` avec des schémas gelés, plus un daemon JSON-RPC
  avec flux de souscription. `gwm statusline` rend un résumé d'une ligne pour tmux, starship ou un
  prompt zsh.

  <Capture
    src={doctor}
    alt="Sortie de gwm doctor : huit contrôles, tous au vert, avec leur ligne de détail"
    cmd="gwm doctor"
    tag="CLI"
    caption="Les mêmes contrôles en --format=json, avec un schéma gelé et un code de sortie sur lequel brancher."
  />
</FeatureRow>

<FeatureRow n="06" title="Corvées de flotte sur tous les worktrees">
  `gwm exec -- cargo test` lance une commande dans chaque worktree avec un récapitulatif par
  worktree, et `gwm clean` liste les répertoires de build récupérables avant toute suppression.
</FeatureRow>

</Section>

<Section pad="column" label="Dans herdr" id="herdr">

[herdr](https://herdr.dev) est un multiplexeur de terminal, et
`herdr-plugin-gwm` y pilote gwm : créer, changer de worktree, supprimer,
matérialiser une PR avec `gwm review`, `exec` et `clean` sur tous les worktrees,
plus la TUI de gwm dans un pane.

gwm reste l'unique source de vérité. Le plugin ne crée jamais de worktree côté
herdr - il adopte ce que gwm a produit et ferme le reflet quand gwm le
supprime, donc les deux ne peuvent pas diverger.

```bash
herdr plugin install kbrdn1/herdr-plugin-gwm
```
