`gwm <sous-commande>` est la face scriptable de gwm. Chaque commande se termine
avec un code significatif (`0` ok, `1` avertissement, `2` échec), de sorte que
vous pouvez la brancher en CI sans parser stdout. `gwm` seul (sans sous-commande)
ouvre la [TUI](/guides/tui/) sur le dépôt courant.

## Worktrees

### `gwm create <type> <issue> <desc>`

Crée un worktree et la branche correspondante.

```sh
gwm create feat 123 user-authentication
#   → branche feat/#123-user-authentication
#   → worktree ~/cc-worktree/<repo>/feat-123-user-authentication
```

| Flag                    | Action                                                         |
| :---------------------- | :------------------------------------------------------------- |
| `--no-bootstrap`        | Saute les étapes de bootstrap de `.gwm.toml`                   |
| `--reuse-branch`        | Se rattache à une branche locale existante au lieu de refuser  |
| `--skip-hooks <PHASES>` | Saute les phases de hook (ex. `pre_create,post_create`)        |
| `--allow-bootstrap`     | Saute l'invite de confiance TOFU sans l'enregistrer (CI)       |
| `--deny-bootstrap`      | Refuse le bootstrap même en cas de confiance (mode forensique) |

Par défaut, `gwm create` refuse de réutiliser silencieusement une branche locale
obsolète — il sort en erreur en nommant le tip obsolète. Déroulé complet :
[Prise en main](/guides/prise-en-main/).

### `gwm new <type> <desc>`

Crée une issue GitHub depuis le formulaire configuré du dépôt, puis le worktree
correspondant au numéro d'issue retourné.

```sh
gwm new feat add-config-types
# → created issue #142 — branch feat/#142-add-config-types
```

Mêmes flags de bootstrap que `gwm create`. Lit `[issue_template]` depuis
`.gwm.toml` (voir [`.gwm.toml`](/reference/gwm-toml/)).

### `gwm list [--format=table|names] [--detect-pr]`

```sh
gwm list                   # table lisible
gwm list --format=names    # un nom par ligne (complétion shell ; exclut le workdir principal)
gwm list --detect-pr       # colonne PR (un appel gh par worktree ; off par défaut)
```

### `gwm path <pattern>` (alias `gwm cd`)

Affiche le chemin sur disque d'un worktree matché en fuzzy. Sort `0` sur une
correspondance unique, `1` sur un échec / une ambiguïté / hors d'un dépôt.

```sh
cd "$(gwm path auth)"
cd "$(gwm cd auth)"
```

À associer à `gwm shell-init` pour le one-liner `gcd`.

### `gwm switch` (alias `gwm s`)

Ouvre la TUI en **mode sélecteur** (filtre pré-ouvert, create/delete/bootstrap
désactivés). `Enter` affiche le chemin surligné sur stdout, `Esc` / `q` /
`Ctrl-C` annule avec le code `1`.

```sh
cd "$(gwm switch)"
```

### `gwm bootstrap [<pattern>]`

Relance le pipeline de bootstrap de `.gwm.toml` sur un worktree sans le recréer.

```sh
gwm bootstrap          # sur le worktree du CWD
gwm bootstrap auth     # sur un nom matché en fuzzy
```

| Flag                                     | Action                                         |
| :--------------------------------------- | :--------------------------------------------- |
| `--skip-hooks <PHASES>`                  | Saute des phases de hook (ex. `pre_bootstrap`) |
| `--allow-bootstrap` / `--deny-bootstrap` | Mêmes flags de confiance TOFU                  |

### `gwm sync [<pattern>] [--merge]`

Récupère l'upstream et met la branche à jour — rebase par défaut, ou merge avec
`--merge`.

```sh
gwm sync               # worktree du CWD, rebase sur l'upstream
gwm sync auth --merge  # merge au lieu de rebaser
```

Garde-fous : arbre sale → refus ; aucun upstream → erreur avec le correctif ;
conflit → rebase/merge **abandonné** pour garder le worktree utilisable.

### `gwm remove <pattern> [--delete-branch] [--dry-run]`

Supprime un worktree (fuzzy). La branche survit par défaut.

```sh
gwm remove auth                  # supprime le worktree, garde la branche
gwm remove auth --delete-branch  # supprime aussi la branche locale (destructif)
gwm remove auth --dry-run        # affiche le plan, ne détruit rien
```

| Flag                    | Action                                                             |
| :---------------------- | :----------------------------------------------------------------- |
| `--delete-branch`       | Supprime aussi la branche locale (destructif)                      |
| `--dry-run`             | Affiche le plan, sort `0`, n'écrit pas dans le journal             |
| `--force`               | Suppression d'urgence : saute les hooks `pre_remove`/`post_remove` |
| `--skip-hooks <PHASES>` | Saute des phases de hook                                           |

### `gwm prune [--dry-run]`

Efface les entrées obsolètes de `.git/worktrees/` dont le répertoire a été
supprimé manuellement. `gwm doctor` signale les entrées élaguables.

### `gwm undo [--bootstrap]`

Annule le dernier `gwm remove` : recrée la branche à l'OID sauvegardé et réajoute
le worktree. `--bootstrap` relance le bootstrap après résurrection.

### `gwm history [--limit N] [--all]`

Liste les opérations destructives récentes (les plus récentes en premier).
`--limit` (défaut 20), `--all` (tous les dépôts). Journal à
`$XDG_DATA_HOME/gwm/history.toml`, plafonné à 100 entrées.

## Configuration

### `gwm init`

Écrit un `.gwm.toml` par défaut dans le dépôt courant. Refuse d'écraser un
fichier existant.

### `gwm config`

Lire, éditer et valider `.gwm.toml` sans ouvrir le fichier à la main.

```sh
gwm config get worktree.base
gwm config set tui.confirm_countdown_secs 5
gwm config set 'labels[+].name=bug'
gwm config unset review.tool
gwm config list --prefix worktree
gwm config validate
gwm config path
gwm config edit
```

Notation par chemin pointé ; `[+]` ajoute une entrée de table de tableau. Les
écritures (`toml_edit`) préservent commentaires et formatage, puis valident.
Schéma complet : [`.gwm.toml`](/reference/gwm-toml/).

## Branche & commits

### `gwm types [--gitmoji]`

Liste les types de branche pris en charge. `--gitmoji` ajoute deux colonnes
(emoji unicode + `:shortcode:`).

### `gwm commit-prefix [--branch <name>] [--unicode]`

Affiche le préfixe Gitmoji + Conventional Commits de la branche courante (ou
nommée).

```sh
gwm commit-prefix             # → :sparkles: feat(#41):
gwm commit-prefix --unicode   # → ✨ feat(#41):
```

### `gwm hooks install commit-msg [--force]`

Installe un hook git `commit-msg` opt-in qui préfixe automatiquement les messages.
Non destructif : refuse d'écraser un hook existant sauf `--force`. `commit-msg`
est le seul type de hook accepté.

## GitHub

### `gwm pr [--draft] [--base <ref>] [--render]`

Rend le corps de PR depuis `[pr_template]` et délègue à `gh pr create` contre le
tronc résolu.

```sh
gwm pr                  # crée la PR
gwm pr --draft          # PR en brouillon
gwm pr --base develop   # diff contre develop
gwm pr --render         # affiche le corps rendu sur stdout (aucune PR créée)
```

Au succès, le numéro de PR est enregistré sous `branch.<head>.gwm-pr`.

### `gwm link {issue|pr} <N> [--worktree <pattern>]`

Lie le worktree à une issue / PR (stocké dans `git config branch.<name>.gwm-issue`
/ `gwm-pr`). Les numéros d'issue des branches `<type>/#<N>-<slug>` sont
**détectés automatiquement** ; `link issue` ne sert qu'aux overrides. Les numéros
de PR ne sont pas auto-détectés.

### `gwm unlink {issue|pr} [--worktree <pattern>]`

Supprime l'override de lien. Idempotent.

### `gwm open {issue|pr} [--worktree <pattern>] [--print-url]`

Ouvre l'issue / PR liée dans le navigateur ; `--print-url` affiche l'URL sans
ouvrir (utile en headless).

### `gwm status [--worktree <pattern>] [--json]`

Affiche le lien + (quand `gh` est dispo) l'état GitHub en direct. Se dégrade
proprement sans `gh`. `--json` pour un schéma stable.

### `gwm labels {list|push}`

Gère l'ensemble déclaratif de labels GitHub depuis `[[labels]]`.

```sh
gwm labels list                 # diff face au remote
gwm labels push                 # applique create + update
gwm labels push --dry-run       # plan seulement
gwm labels push --prune         # supprime aussi les labels non déclarés (destructif)
gwm labels push --random-colors # pastel aléatoire pour les entrées sans color
```

Sans bloc `[[labels]]`, c'est un no-op. Nécessite `gh` sur le `$PATH`.

### `gwm milestones {list|push}`

Même forme que `gwm labels` pour les milestones (`[[milestones]]`). Flags
`--dry-run`, `--prune`. Utilise l'endpoint REST via `gh api`.

## TUI & thèmes

### `gwm theme {list|show <name>}`

Inspecte les presets de couleurs TUI intégrés.

```sh
gwm theme list                 # noms des presets intégrés
gwm theme show catppuccin      # dump du preset en bloc [theme]
```

Presets : `catppuccin`, `gruvbox`, `tokyo-night`, `claude-dark` (alias `claude`).

### `gwm tui keys`

Affiche le keymap TUI résolu (défauts + overrides `[tui.keys]`) avec la source
par ligne. Voir [La TUI](/guides/tui/).

## Multiplexeur & shell

### `gwm tmux <pattern> [-p|--split]`

Ouvre le worktree matché dans une nouvelle fenêtre tmux (ou un split avec `-p`).
Nécessite `$TMUX`.

### `gwm zellij <pattern> [-p|--split]`

Comme `gwm tmux` pour zellij (`new-tab --cwd`, ou `new-pane --cwd` avec `-p` ;
nécessite zellij ≥ 0.40 pour `--cwd`). Nécessite `$ZELLIJ`. Détail :
[La TUI](/guides/tui/).

### `gwm completions <shell>`

Affiche un script de complétion statique. Shells : `zsh`, `bash`, `fish`,
`powershell`, `elvish`.

### `gwm shell-init <shell>`

Affiche le wrapper de shell `gcd`. Shells : `zsh`, `bash`, `fish`, `powershell`.

## Diagnostic & confiance

### `gwm doctor`

Lance les vérifications de santé ; rapporte `✓ / ! / ✗` ; sort `0 / 1 / 2`.
Conçu pour la CI et les hooks pre-commit. Détail par vérification :
[Diagnostic (doctor)](/guides/doctor/).

### `gwm trust {list|revoke|show}`

Gère le registre de confiance TOFU qui conditionne le bootstrap.

```sh
gwm trust list                                # toute paire (origin, hash) approuvée
gwm trust revoke git@github.com:foo/bar.git   # supprime les entrées d'un origin
gwm trust show                                # chemin du registre + TOML brut
```

Registre par défaut : `~/.config/gwm/trust.toml` (`$GWM_TRUST_LEDGER` pour
surcharger). Modèle de menace : [Trust ledger (TOFU)](/concepts/trust-ledger/).

## Alias

### `gwm aliases list`

Affiche la chaîne d'alias CLI résolue, groupée par source (intégré → dépôt →
utilisateur). En lecture seule ; l'édition se fait dans `[aliases]` de
[`.gwm.toml`](/reference/gwm-toml/) ou `~/.config/gwm/aliases.toml`.

## Codes de sortie

<Aside type="tip">
  Les codes sont stables et scriptables — branchez `gwm doctor` ou `gwm bootstrap` en CI sans parser
  stdout.
</Aside>

| Code | Signification                                                           |
| :--- | :---------------------------------------------------------------------- |
| `0`  | succès — aussi « tout au vert » pour `gwm doctor`                       |
| `1`  | échec récupérable — échec fuzzy, correspondance ambiguë, Warning doctor |
| `2`  | échec dur — bootstrap `✗`, Failure doctor, erreur git irrécupérable     |
